# 需求（requirements）

## 一、要解決的問題

翻新舊系統前需要到客戶端現勘，逐一盤點既有頁面與功能。人工用紙筆或臨時筆記容易漏記畫面元素（欄位、按鈕、查詢條件、報表等），後續整理需求文件時資訊不齊。本工具提供一份結構化、離線、隨開即用的現勘紀錄畫面，確保逐項記錄且輸出格式一致。

## 二、使用情境

- 現勘人員攜帶筆電，在客戶端內網環境（可能無外網）開啟本工具。
- 依舊系統的頁面／功能架構，逐一建立節點並填寫畫面資訊與元件細節。
- 現勘結束後匯出成果，帶回公司彙整成需求文件。

## 三、輸入

- 使用者手動輸入：客戶名稱、現勘日期、備註等基本資料。
- 樹狀「頁面／功能架構」：節點名稱、層級關係。
- 各節點的畫面資訊欄位（使用頻率、使用角色與權限、用途說明、前置條件、相關法規／規範、已知問題／使用者抱怨、截圖）。
- 各節點掛載的元件卡：依元件類型（下拉選單、輸入框、日期／區間、Radio、Checkbox、按鈕與動作、查詢邏輯、結果清單、報表匯出、錯誤與提示、自訂備註）填寫對應檢查項目。
- 截圖檔（上傳後壓縮存入）。

## 四、輸出

- **JSON**（主力）：`{meta, tree}`，每個節點附上算好的 `menuPath`；可回頭載入續填。相容舊的平面 `screens` 格式。
- **Markdown**：先輸出縮排的架構圖，再逐節點列出選單路徑、已填欄位與元件，供貼進需求文件。

## 五、非功能需求

- 單檔、離線、免安裝、免建置：以瀏覽器雙擊即可執行。
- 不依賴外部資源與網路，適用客戶端封閉環境。
- 資料以使用者可掌握的檔案（JSON）保存，不強制依賴瀏覽器儲存。

## 六、範圍外（目前不做）

- 不做後端、不連資料庫、不做多人協作或雲端同步。
- 不自動抓取舊系統畫面，所有紀錄由現勘人員手動填寫。
