# 設計（design）

## 一、技術與架構

- 單一自足的 HTML 檔（`legacy-survey-tool.html`），CSS 與 JS 全部內嵌，可離線雙擊開啟。唯一的對外連線是字體（見第四節），且離線會自動退用本機字體，不影響功能。
- 純 vanilla JS，無框架、無建置流程。刻意如此以確保「單檔、離線、隨開即用」。
- **資料驅動畫面**：畫面上的每個欄位、每張元件卡，都是程式讀「定義物件」自動長出來的。要擴充欄位或元件，改設定區即可，不必動繪製邏輯。

## 二、資料模型（存於 `STATE`）

```
STATE = { meta:{client,date,note}, tree:[node], selected:nodeId, treeHidden:bool }
node  = { id, name, collapsed, children:[node], fields:{}, components:[comp] }
comp  = { id, type, label, collapsed, fields:{} }
```

- 樹狀「頁面／功能架構」：每個節點可掛畫面細節（`fields` ＋ `components`），中間分類節點可空著只做分組。
- 選單路徑自動帶入：某節點的選單路徑＝它在樹上一路往上的祖先名稱串接（以麵包屑顯示、並寫入匯出）。

## 三、設定區（擴充改這裡，在 `<script>` 最上方）

- **`SCREEN_FIELDS`**：節點層級（畫面資訊）欄位。目前有：使用頻率、使用角色與權限、用途說明、前置條件、相關法規／規範、已知問題／使用者抱怨、截圖。
- **`COMPONENT_TYPES`**：元件類型，每個含 `icon`（內嵌 SVG 路徑字串）與 `fields[]`。目前類型：下拉選單、輸入框、日期／區間、Radio（單選）、Checkbox（複選）、按鈕與動作、查詢邏輯、結果清單、報表匯出、錯誤與提示、自訂備註。
- **欄位型態（`type`）**：
  - `check`：是／否／待確認。
  - `req`：是／否／選擇性／待確認；選「選擇性」會出現「必填條件」輸入框（條件值存在 `該key_cond`）。
  - `choice`：自訂選項的單選按鈕，需在欄位加 `opts:[[值,顯示文字],…]`。
  - `multi`：自訂選項的多選按鈕（值為陣列），同樣需 `opts`。
  - `text` / `textarea`：文字（可加 `hint:'…'` 當提示文字）。
  - `images`：多張截圖上傳（壓縮後存進存檔）。

## 四、主要流程與關鍵決策

- **主從式版面**：左樹（可隱藏）＋右詳細；視窗 < 860px 自動上下堆疊。
- **樹狀操作**：新增頂層／子節點、刪除（按兩下確認）、收合、選取；雙擊節點名稱就地改名（Enter／點空白處完成、Esc 取消）。選取節點時只重繪右側詳細（`refreshDetail`），不重建整棵樹，雙擊改名才成立。
- **拖曳排序**：用左側六點握把拖曳；上緣＝前、下緣＝後、中間＝成為子節點；擋掉拖進自己子孫。
- **元件收攏鈕**：收攏後只留欄位名稱＋元件類型。
- **截圖**：上傳等比縮到最寬 1600px、轉 JPEG（品質 0.72）後以 base64 存進 JSON。
- **配色**（全走 CSS 變數，定義在 `:root`）：底 `#EEEADB`、主色 `#4C5760` 石板藍灰、完成/進度 `#93A8AC` 鼠尾草（深 `#6E8A90`）、強調 `#D7CEB2` 沙、中性線 `#A59E8C` 灰褐、文字 `#3F484F`、警示 `#A6604B`。以內嵌 SVG icon 區分元件類型（非用顏色）。
- **字體**（集中在 `--sans`／`--mono` 兩個 CSS 變數）：採「連線下載＋離線本機」兩層備援。`<head>` 以 `<link>` 向 Google Fonts 載入 Noto Sans TC（100~900 字重）；另有一個只含 `local()` 的 `@font-face`（`"Noto Sans TC Local"`）指向本機已裝的 Noto Sans TC。`--sans` 解析順序為：本機 Noto Sans TC → Google 下載版 → 微軟正黑體 → 系統字體。因此連線時保證有 Noto Sans TC，離線且本機有裝時走本機，皆無則退用微軟正黑體。

## 五、儲存與匯出

- `localStorage` 自動暫存（盡力而為、包 try/catch）＋ JSON 匯出／載入（主力）＋ Markdown 匯出。
- JSON 為 `{meta, tree}`，每個節點附上算好的 `menuPath`；舊的平面 `screens` 格式在 `normalize` 時自動轉成頂層節點。
- Markdown 先輸出縮排架構圖，再逐節點列選單路徑、已填欄位與元件；`req` 顯示「選擇性（條件）」，`multi` 顯示選項串接，`choice` 顯示中文選項。`buildMarkdown(imgPathById)` 傳入圖片路徑對映時，圖片欄改輸出 `![名稱](相對路徑)`；不傳（純文字匯出）維持「N 張（檔名）」。
- **下載打包（zip）**：`buildBundle` 產生一個 zip，含存檔 JSON（保留完整 base64，可載回）、帶圖片相對路徑的 Markdown，及依功能樹狀階層擺放的圖片。相關函式：`bundleImages`（走訪樹狀，產出 圖片檔清單 與 `圖片id→相對路徑`，資料夾／檔名以 `sanitizeName` 清理、同層／同資料夾同名加序號）、`crc32`＋`zipStore`（純 JS 內建的最小 ZIP，store 不壓縮、檔名走 UTF-8，不依賴外部套件以維持離線）。
- 圖片上傳後以 `nameCmp`（`localeCompare` 的 numeric 模式）對整欄自然排序。

## 六、驗證方式

- 本端無法真的開瀏覽器預覽或執行互動。做法是抽出 `<script>` 用 `node --check` 驗語法，再用最小假 DOM 在 Node 實際執行邏輯函式（進度、Markdown、樹搬移、`normalize` 等）比對輸出。
- 上述做法已落地為 `tests/test.cjs`（不依賴套件），於工具資料夾內以 `node tests/test.cjs` 執行。
- 視覺與互動手感須在真實瀏覽器驗收。

## 七、是否必填欄位（已完成）

需求「每個元件都再加是否必填欄位（`req` 型態，選項同下拉選單）」已完成：

- 現況：除「自訂備註」外，所有元件都有「是否必填／必選」（`req` 型態，選項為是／否／選擇性／待確認；選「選擇性」會出現必填條件欄）。
- 本次補齊：查詢邏輯、結果清單、報表匯出、錯誤與提示。
  - 「錯誤與提示」原本已有一個 key 叫 `req`（那是「必填未填的提示」textarea），故新加的是否必填改用 `required` key，以免衝突。
- 「自訂備註」不加（經確認）：它是純備註容器，加是否必填無意義。
- 對應驗證見 `tests/test.cjs` 的「元件是否必填欄位齊備」。

其餘後續事項與細節見 `handoff-notes.md`。
